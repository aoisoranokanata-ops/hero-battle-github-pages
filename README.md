# 英雄列伝バトル 神々編

紙カード108枚を使う、2人・1台の対戦補助ブラウザアプリです。Phase 1を実装しています。GitHub Pagesでの公開・URLからの利用を標準とします。HTML / CSS / Vanilla JavaScript / localStorageだけで動き、バックエンド・外部API・CDNは使用しません。利用端末にExcel、Node.js、Pythonをインストールする必要はありません。公開ページの読み込みにはインターネット接続が必要です。

## 利用方法（GitHub Pages）

1. 管理者が、下記の公開手順でファイル一式をGitHub Pagesへ公開します。
2. iPad、Android、Windowsのブラウザから同じ公開URLを開きます。利用者によるZIP解凍やローカルHTML実行は不要です。
3. 「デッキを作る」で10枚を選び、デッキ名を付けて保存します。
4. 「対戦を始める」で2人のデッキ、先攻、対戦時間を選びます。
5. 紙で引いた初期手札を登録して対戦開始。その後も、紙で引いたカードをタップして登録します。

保存データは端末・ブラウザごとです。同じURLでも、デッキや試合は端末間で同期されません。2人で1台を共有して対戦します。別ブラウザへの切り替えや保存データ削除で、以前の保存内容を参照できなくなることがあります。保存が拒否された場合は画面上部に表示します。

開発時にHTTPで確認する場合だけ、フォルダー内で以下を実行できます。バックエンドではなく静的ファイルの配信です。

```sh
python -m http.server 8765 --bind 127.0.0.1
```

その場合はブラウザで `http://127.0.0.1:8765` を開きます。`file://` とHTTP版の保存領域は別です。

## 実装した機能

- タイトル、カード検索・レアリティフィルター、108枚の原文詳細表示。
- 10枚のデッキ構築、UR最大1・SSR最大2・SR最大3・R最低4の検証。同一ID重複なし。URなしも許可。
- デッキ名、任意のプレイヤー名・チーム名の保存。編集・複製・確認付き削除。
- 2人分のデッキと先攻選択。実際に紙で引いたカードを初期手札・ドローとして登録。ランダム抽選なし。
- 山札・手札・場・トラッシュ管理。手札を隠す、手札を捨てる、トラッシュ内容確認。
- ライフ・エネルギー管理、場の上限、コスト補正と消費、召喚ターン攻撃不可。
- 攻撃−防御、最低ダメージ、直接攻撃、攻撃済み管理、兵力0の確認とトラッシュ移動。
- 攻撃開始時の敵陣を記録。敵陣突破で攻撃フェイズ終了、同ターンに再開不可。
- スキル・特性全文、攻撃・防御・現在兵力・最大兵力の補助、3種類の状態、効果メモ、攻撃済み解除。
- ライフ0の勝利表示、勝者名・チーム名表示。
- タイマー：10・12・15・20分、任意1～180分、一時停止と再開。
- 時間切れ判定：ライフ → 場の現在兵力合計 → 手札枚数 → 引き分け／代表カード決戦。
- 50操作のUndo、時刻付きの直近500件の対戦ログ。
- 試合・各カードの現在値・状態・メモ・ターン・タイマー・ログ・Undo履歴の自動保存と再開。
- 先生向け設定と標準ルール復帰。変更は次の新規試合から適用。
- 横画面は左右、縦画面は上下配置。日本語、大きなボタン、色と文字による状態表示。

## Excel更新後の再生成

Python 3.9以降で、プロジェクトフォルダー内から実行します。追加パッケージは不要です。Excelの正本パスを引数に渡してください。

```sh
python tools/xlsx_to_cards.py "C:\path\英雄列伝バトル_108枚統合管理表.xlsx"
```

出力先を指定する場合：

```sh
python tools/xlsx_to_cards.py "C:\path\正本.xlsx" --output cards-data.js
```

シート名・5行目の見出し・総数・レアリティ内訳・重複ID・主要項目・数値型を検証します。カード欄の数式は、未計算の値を補完しないため拒否します。検証に失敗すると明確なエラーを表示して終了し、既存の`cards-data.js`を上書きしません。

再生成後はテストを実行し、ブラウザを再読み込みしてください。試合途中で原本を更新した場合、保存済みの現在数値と新しい能力文が混在するため、その試合を終えてから更新し、新規試合を開始してください。ハッシュ差がある保存試合の再開時には通知します。

## 保存とルール処理の詳細

- 保存キーは `hero-battle-v1:decks`、`hero-battle-v1:settings`、`hero-battle-v1:match` です。外部への送信、分析、広告、アカウント機能はありません。
- CSPでも`connect-src 'none'`を指定しています。全JS/CSSは同じ配信元の相対パスで読み込み、GitHub Pagesのリポジトリ名付きURLでも動作します。
- 自分の初回ターンは開始エネルギー（標準1）。次の自分のターンで最大値＋1・全回復します。先攻・後攻どちらの初回もドローがあります。
- ターン開始時は紙のドロー登録を促し、登録まで召喚・攻撃開始・ターン終了を止めます。追加ドローの効果は通常のドローボタンから手動で処理できます。
- 召喚は準備フェイズで行います。攻撃開始後は追加召喚できません。
- 攻撃済みと召喚ターンのフラグだけを次の自分ターンで解除します。攻防補正・攻撃不能・無効状態・効果メモは自動解除しません。
- 現在エネルギーの手動増加は先生設定の最大エネルギーまでです。そのプレイヤーの自然成長した最大値は変更しません。
- 兵力0の確認は「あとで確認」で保留できます。保留中はカードに警告が残り、そのカードは攻撃できません。ターン終了前にトラッシュへ移す必要があります。トラッシュ確認後、敵陣突破なら自動で攻撃フェイズが終了します。
- Undoは確認後に直前のスナップショットへ戻り、タイマーも当時の残り時間へ戻ります。トラッシュ移動と、その前のダメージは別操作です。攻撃を取り消す際は必要に応じて2回戻してください。
- タイマーは一時停止しない限り、タブ移動・ブラウザ終了中も実時間で進みます。再起動時に期限を過ぎていれば時間切れ判定を行います。
- 名前やデッキ、手札は同じ端末を使う人が操作できます。手札の非表示は対戦マット上の表示切り替えです。対戦ログにはドロー記録が残ります。


結果：ルール・データ33件、変換5件、すべて成功。指定されたUR2・SSR3・SR4・R3の違反、正常構成、エネルギー5/6でのコスト6、場の4枚目、ダメージ2/最低1、兵力0、直接攻撃A/B、復元を含みます。加えて召喚制限、再攻撃、状態保持、回復上限、ライフ勝利、時間切れの各比較順序を検証しています。

ブラウザテストには開発用のPlaywrightが必要です（アプリ実行には不要）。Playwrightとそのブラウザを用意した環境で実行できます。

```sh
node tests/browser.test.cjs
```

```powershell
$env:BROWSER_EXECUTABLE = 'C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe'
```

`PLAYWRIGHT_MODULE`で既存Playwrightのパス、`SCREENSHOT_DIR`で検証画像の出力先を指定できます。テストは独立したブラウザコンテキストを使い、普段利用するブラウザの保存データを変更しません。

## GitHub Pagesへの公開方法

1. `hero-battle-github-pages.zip` を展開し、中身をリポジトリのルートへ置きます。ZIPの直下に `index.html` があります。親フォルダーを追加せず、`index.html`と各JS/CSS、`.nojekyll`を同じ階層に保ちます。
2. 公開するブランチへコミットします。
3. リポジトリの **Settings → Pages → Build and deployment → Source** で **Deploy from a branch** を選択します。
4. 対象ブランチと **/(root)** を選んで保存します。
5. デプロイ完了後、表示された公開URLを開きます。

上記は[GitHub公式の公開元設定手順](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)に基づきます。今回、外部への公開は行っていません。リポジトリにプレイヤー名や試合データを含める必要はありません。アプリの保存は利用者のブラウザ内です。GitHub Pagesで初めてページを取得する際にはインターネット接続が必要です。完全にオフラインで使う場合はファイル一式を端末に置いてください。

## 残っている課題・対象外

- チーム3～4人の大会登録とチーム全体UR最大2枚チェックはPhase 2として未実装です。Phase 1のプレイヤー名・チーム名登録は実装済みです。
- スキル108枚の自動解析・自動実行は仕様どおり未実装です。「先に攻撃する」「かばう」などの扱いは相談し、手動補助・メモで処理します。
- iPad Safari、Android、Chromebook実機は未検証です。今回検証したのはWindows Edgeと各画面幅です。端末固有のローカルHTML起動・保存制限は実機で確認してください。
- 複数端末への保存データ同期、複数タブ同時編集、デッキ／試合のファイル書き出し、オフライン用Service Workerは含みません。
- 原本のバランス調整や能力文の変更は行っていません。
