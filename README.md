# 英雄列伝バトル 神々編 — Phase 3

GitHub Pagesで使う、2人・1台の静的な対戦補助アプリです。HTML・CSS・JavaScript・localStorageのみを使用し、バックエンド、外部API、CDN、分析ツールはありません。紙カードは場に出す時に並べ、山札・手札の順番と位置はアプリが管理します。

## GitHubへのPushで更新

このGit作業フォルダーで編集し、`main`へPushして更新します。操作は[UPDATE.md](UPDATE.md)を参照してください。`index.html`はリポジトリのルートに配置されています。

公開URL：[英雄列伝バトル 神々編](https://aoisoranokanata-ops.github.io/hero-battle-github-pages/)。公開ページの取得にはインターネット接続が必要です。GitHub Pagesのデプロイ完了後、同じURLをWindows、iPad、Androidのブラウザで開きます。配布済みQRコードも引き続き利用できます。

## 特殊スキル・プリセット（2026-09-20）

先生向け設定 → **特殊スキル設定**で、カードとスキル／特性を選び、処理タイプを指定します。Excel由来の本文は画面にそのまま表示し、変更しません。

- **AUTO**：既存の自動処理を使います。従来の対象選択付き処理（内部のSELECT）も動作を維持します。確定した自動処理がない能力では選択できません。
- **PRESET**：対象・能力・増減値・期限を最大3件登録します。対戦中に「スキル発動（PRESET）」を押すと処理します。対象選択が必要な効果はすべて選んだ後にまとめて適用します。
- **MANUAL**：数値だけでは表現できない能力を裁定します。設定でMANUALを指定した能力は自分のターンに発動ボタンで手動処理に進みます。未設定の能力は従来の処理を維持します。

本文の条件判断をプリセットが代行することはありません。発動条件を確認してから操作してください。初期状態では独自の数値効果を推測して登録していません。複雑な効果はMANUALのまま使ってください。

「攻撃 +2」等の簡単ボタンは効果1を自分自身への効果に設定します。対象・期限は続けて変更できます。変更値は候補−5～+5、または0以外の−999～999の整数です。ライフ・エネルギーはプレイヤー、攻撃・防御・現在兵力・最大兵力は場のカードが対象です。

期限は即時／このターンのみ／次の自分の開始まで／次の相手終了まで／永続。攻撃・防御・最大兵力は基本値を固定した補正です。現在兵力・ライフ・エネルギーを期限付きにした場合は、実際に加減できた分を期限で逆算して解除します（その後のダメージ等を保持し、上限・下限を適用）。即時の変更は自動で戻しません。最大兵力の変更だけでは現在兵力を回復しません。兵力0やライフ0になれば通常の撃破・勝敗判定を行います。

回数は1ターンに1回／1試合に1回／制限なし。ターン制限は次の自分のターンで回復します。試合制限は同じカードを場に出し直しても維持します。数値・発動済み・対象選択・ログ・撃破はまとめてUndoできます。

設定は`hero-battle-v1:skill-presets`に保存し、新規試合へ複製します。設定変更・初期化は進行中の試合や保存済み試合には反映しません。「この能力を標準に戻す」「特殊スキル設定を初期化」で設定を解除できます。デッキ・試合は削除しません。プリセットの保存は端末・ブラウザごとです。

処理は`skill-presets.js`、設定UIは`preset-editor.js`で管理します。`cards-data.js`・`automation-data.js`・Excelは変更していません。原文が設定時と変わったプリセットはMANUALへ退避します。

検証：プリセットのルール15件、ブラウザ6項目（設定保存、対象選択途中の再開、一括Undo、二重発動防止、期限バッジ、初期化、狭幅表示）。

```sh
node --test tests/presets.test.cjs
node tests/presets-browser.test.cjs
```

## Phase 3の追加機能

- 「効果」パネルで補正の期限を選べます。初期選択は「このターン終了まで」。次の持ち主のターン開始まで／場にいる間も指定できます。現在兵力へのダメージ・回復は即時処理です。
- 基本攻撃・防御・最大兵力はExcel由来の値を保持し、永続補正と期限付き補正を分離します。カード詳細に内訳、場に期限バッジ、ログに適用・終了時の値を表示します。
- 初期手札と通常ドローは、それぞれ「ランダム／手動」を選べます。標準は両方ランダム、初期3枚です。手動初期手札では2人が端末を受け渡して必要枚数を選び、両者の選択後にタイマーを開始します。通常の手動ドロー完了後にエネルギー回復とターン開始能力を処理します。
- 新規試合の通常ランダムドローは残り山札から1枚を無作為に抽出します。カード能力によるドロー・山札並べ替えは既存の能力処理を維持します。Phase 2から再開した試合でドロー方法が未設定の場合は、従来の山札先頭から引く方式を保ちます。
- サウンドと映像演出は別々に設定し、音量は標準70％。右上のサウンドボタンでも即座に切り替えられます。設定はlocalStorageに保存します。
- 開始約2.6秒、攻撃約0.4秒、撃破約0.65秒、勝利約2.6秒の演出。勝者を祝う紙吹雪だけを使い、引き分けには紙吹雪を出しません。
- 画像と音声は提供素材を同梱し、同じ配信元から事前読み込みします。開始は「開始.png＋合戦場で軍勢が突撃」、攻撃は「攻撃.png＋高速斬撃1」、トラッシュは「トラッシュ.png＋倒れる」、終了は「ゲーム終了.png＋笛ピッピー2」です。画像表示と音を同じ場面で開始します。攻撃→トラッシュ→終了が同時に発生した場合も、この順に表示します。
- 開始2.6秒・攻撃0.4秒・トラッシュ0.65秒・終了2.6秒。長い音は場面の終わりで短くフェードアウトします。素材ファイル自体は変更していません。音OFFでも画像を表示し、演出OFFでも音ONなら音は再生します。素材取得・音声APIの失敗で対戦処理を停止しません。
- 演出前にゲーム状態を保存し、演出は状態を書き換えません。短時間のボタン無効化で二重操作を防ぎます。Undo・再開では演出を再生しません。

Phase 2の保存キーを引き続き使用します。旧保存内で基本値に加算されていた手動補正は永続補正へ移し、現在値を維持します。過去の手動補正には期限情報がないため、勝手に「今ターンのみ」と推測しません。必要な期限は効果パネルで再設定してください。カード原文・能力対応表は変更していません。

## Phase 1からの引き継ぎ

- 保存デッキと先生設定は既存のキーを引き継ぎます。
- Phase 1の進行中試合は変更しません。タイトル画面の「保存済みPhase 1の試合を旧ルールで続ける」から、同梱の `legacy/index.html` で再開できます。
- Phase 2の新規試合は別の保存キーを使います。旧試合へ自動化を後付けすると、手動補正との二重適用が起きるため、自動移行は行いません。
- 従来の攻撃・防御・兵力・最大兵力・エネルギー・ライフ・状態・メモの手動調整は残しています。
- 新規試合の山札切れは常に敗北なしです。Phase 1の「山札切れ敗北」設定はPhase 2では適用しません。

保存は端末・ブラウザごとです。同じURLでもデッキや試合が端末間で同期されるわけではありません。以前と同じホスト名・ブラウザで更新すると既存の保存領域を使えます。

## 追加した処理

### 山札とターン

10枚をFisher–Yates方式でシャッフルし、初期手札を自動配布します。標準は3枚。初回の準備OK後にも、そのプレイヤーのターン開始として1枚ドローします。

ターン開始 → 設定した方法で1枚ドロー → 最大エネルギーを更新 → 全回復 → ターン開始の能力 → 操作開始、の順で進みます。初回エネルギーは標準1、以後は自分のターンごとに＋1、標準上限10です。

山札0枚時はドローを省略し、プレイヤーごとに一度だけ案内とログを出します。手動裁定用の「追加ドロー」も残しています。通常の山札一覧は順番・内容を公開しません。

### 手札の秘匿

相手の手札は枚数と裏面だけを表示し、カード名を対戦画面のDOMに描画しません。ターン終了時は全画面の交代画面へ移り、準備OKまでは両者の手札内容を表示しません。

相手に手札を選んで捨てさせる効果も、相手へ受け渡し → 相手が選択 → 元のプレイヤーへ受け渡し、の順です。自動ドローや非公開の山札操作はログにカード名を記録しません。公開して手札へ加える効果やトラッシュのカード名は公開情報として記録します。

再読み込み、試合画面からの移動、タブ非表示、Undoの後も手札をロックします。これは共有端末の画面上の秘匿です。保存データは端末内にあるため、開発者ツール等からの閲覧を防ぐ認証機能ではありません。

### 撃破とライフ

兵力0の場カードは確認ダイアログなしでトラッシュへ移動します。原本の元コスト1～4はライフ−1、5以上は−2。召喚時のコスト軽減は影響しません。兵力が残ったカードの手動トラッシュや手札破棄には撃破ダメージを課しません。

最後の敵を倒した場合も撃破ライフ減少が発生します。攻撃開始時に敵の場が存在したなら、敵陣突破の案内とともに攻撃フェイズを終了し、同ターンの直接攻撃・フェイズ再開を禁止します。

本多忠勝の一度だけ兵力1で残る能力は、撃破処理の前に自動判定します。適用した場合はまだ撃破ではないため、ライフは減りません。

### 能力の自動化

108枚・216能力をスキルと特性に分けて分類しています。カード単位の集計は以下です。

| 分類 | 枚数 | 処理 |
| --- | --- | --- |
| AUTO | 45 | 選択のない処理を自動実行 |
| SELECT | 55 | 対象・順番・任意の選択後に数値を自動処理 |
| MANUAL | 8 | 解釈が必要な能力を含む。該当能力だけ手動 |

カードにMANUAL能力があっても、別の確定したスキル・特性は自動で処理します。分類は `automation-data.js` に原文照合情報とともに持ち、実行時の `Game.automationType(id)` で参照します。元の `cards-data.js` の18列は変更していません。

自動処理には登場時、ターン開始時、条件付きの継続効果、期限付き攻防補正、無効状態、コスト軽減、回復、ドロー、エネルギー、撃破後の強化・回復、戦闘生存時の回復が含まれます。山札の並べ替え・候補から選ぶ・手札破棄・最大3体の選択も対応しています。

発動済みを能力ごとに保存し、登場時の再実行、1ターン1回・1試合1回の二重使用を防ぎます。「スキル発動！【継続効果】」は条件を満たして現在働いている能力です。押すと説明が開き、効果は重ねがけされません。

自動補正は手動補正から分離し、明確な期限で自動解除します。手動調整のリセットは手動値を原本に戻し、現在有効な自動効果は残します。無効状態のチェックも手動設定を変更するもので、有効期限内の自動付与は期限まで残ります。

MANUAL能力はその能力全体を自動実行せず、原文と理由を表示します。自動部分との二重処理を避けるためです。数値・状態は手動補助で調整してください。孫子のランダムな相手手札確認など、手動分類の特別なカード開示を自動で行う機能は含みません。先生の裁定が必要です。

### Undoと保存

召喚 → 対象選択 → 相手の手札破棄 → 後続効果、または攻撃 → 兵力減少 → トラッシュ → 撃破ライフ減少を、発端となる1操作へまとめます。選択途中で再読み込みしても処理待ちとUndoグループを保持します。

50操作まで戻せます。対戦ログは直近500件。Undoはカード位置・数値・能力使用状態・山札順序・効果の期限を戻し、タイマーもその操作前の残り時間へ戻します。タイマーは一時停止しない限り、ページを閉じた間も経過します。

保存キー：`hero-battle-v1:decks`、`hero-battle-v1:settings`、`hero-battle-v1:match-v2`。旧試合は `hero-battle-v1:match` に残します。

## Excel更新時

正本は受領した `英雄列伝バトル_108枚統合管理表.xlsx`。シート「108枚統合管理表」、5行目見出し、6～113行の108枚です。内訳UR9・SSR27・SR27・R45。元Excelは変更していません。

```sh
python tools/xlsx_to_cards.py "正本.xlsx"
node tools/build-automation.cjs
node --test tests/game.test.cjs tests/phase2.test.cjs tests/phase3.test.cjs
python tests/converter.test.py "正本.xlsx"
```

Excel変換はPython標準ライブラリのみ。分類表生成・テストにはNode.jsを使用しますが、ブラウザでの実行には不要です。原文が変わった能力はレビュー済み文と一致しないためMANUALへ退避します。`reviewed-source.json`だけを機械的に更新せず、原文に合わせて処理定義とテストを確認してから更新してください。

データ変更は試合を終えてから行ってください。古い保存試合の現在値は保持されますが、読み込む能力文は配信中のデータです。更新中の試合に新しい数値や能力を混在させない運用を推奨します。旧仕様の `legacy/` 内のデータは、既存試合のために更新対象から分けています。
